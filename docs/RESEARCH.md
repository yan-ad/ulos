# Research notes and sources

Reference date: 2026-10-14. Sources describe upstream behavior, not proof that Ulos builds or supports a platform. Recheck requirements when locking dependencies or preparing releases.

## GPUI Kit

- [Installation](https://gpui-kit.com/docs/installation)
- [Getting Started](https://gpui-kit.com/docs/getting-started)

The consulted installation guide presents GPUI Kit 0.7.3 and Rust 1.92+ for its current locked dependency graph (including Linux's `oo7` dependency). It lists macOS 15+ with Xcode Command Line Tools, and Windows 10+ with Visual Studio 2022 C++ tooling/MSVC, a Windows SDK, and CMake. These are upstream setup baselines, not a tested Ulos support policy.

For Linux the guide lists verified Ubuntu 24.04 development packages, with equivalents needed on other distributions: compiler tooling, fontconfig, Wayland, WebKitGTK 4.1, XKB/X11 integration, OpenSSL/zstd, and Vulkan loader/validation libraries. ALSA development headers are needed only for the speech feature. A graphical X11 or Wayland session with a working Vulkan driver is required; a Vulkan loader alone is not a GPU driver. Check the selected features and dependency graph before deciding what Ulos actually needs.

The getting-started guide uses `gpui-kit` as the single aligned UI dependency, calls Kit initialization before opening windows, and registers assets. Kit enables macOS text rendering support. Follow the matching release API rather than mixing independently selected GPUI snapshots. GPUI Fast is optional upstream; selecting it is not a Ulos decision or a performance claim.

These notes are an original concise summary of linked GPUI Kit guidance, not copied examples. GPUI Kit documentation credits its prose under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) and its software/code examples under Apache-2.0. Those terms do not select a license for Ulos.

## Native windows and semantic components

Checked 2026-10-14 against the upstream pages below, summarized here in original wording (not copied prose/example chunks):

- [Window](https://gpui-kit.com/docs/window): window handles select the target context and can fail after close; deferred updates avoid reentrant window/entity access. Focused action dispatch and entity notifications are distinct from native-window state changes. Ulos uses this boundary for typed macOS menu routing and keeps Options on the main handle.
- [Tooltip](https://gpui-kit.com/component/tooltip): Kit exposes public `component::tooltip::Tooltip` and built-in `Button::tooltip`. Ulos uses Button tooltips with explicit accessible labels for stock icon actions; no separate `gpui-tooltip` dependency is needed.
- [Multi Window](https://gpui-kit.com/docs/multi-window): Kit opens a separate Root per window; content entities, intended window handles, local subscriptions, close guards, registry cleanup, and last-window quit policy are distinct responsibilities. Ulos keeps child-context input and subscriptions, strong child-to-manager ownership, and weak reverse registries. The manager still combines view and shared session ownership; extracting a dedicated model is future refactoring, not current architecture.
- [Sidebar](https://gpui-kit.com/component/sidebar): Kit supplies grouped menus, icon-mode collapse, default 255px/48px widths, a 200ms frame-clock transition, and collapsed-item tooltips. Ulos uses the pinned `Sidebar` / `SidebarGroup` / `SidebarMenu` / `SidebarMenuItem` API, with flat Downloads and File types groups rather than an All-downloads subtree. The application owns counts, active filter, accessible names, and session-only collapse state. Some documentation examples have outdated signatures; use the pinned dependency API rather than transplanting examples. `SidebarToggleButton` forces ghost/small presentation, so Ulos uses an unmodified toolbar Button with stock PanelLeft icons instead. These are source/API observations, not native animation, focus/arrow-navigation, or accessibility verification.
- [DataTable](https://gpui-kit.com/component/data-table): retained TableState plus a delegate provides viewport virtualization, column sorting and row events. Ulos uses snapshot rows and Kit Checkbox/Button/Label cells, retaining stable record-ID checkbox selection separately from positional table navigation.
- [Toolbar](https://gpui-kit.com/component/toolbar) and [StatusBar](https://gpui-kit.com/component/status-bar): compose command rows and session status through Kit semantic containers rather than hand-built widget surfaces. The Toolbar page documents that `child` propagates size and forces ghost/compact Button presentation. Ulos deliberately uses `content` to preserve stock controls under its stricter no-control-styling policy; wrapper geometry remains layout-only.
- [GroupBox](https://gpui-kit.com/component/group-box) and [DescriptionList](https://gpui-kit.com/component/description-list): group destination/status panels and present telemetry label/value pairs with Kit components.
- [Empty](https://gpui-kit.com/component/empty): named content slots present missing downloads or filtered-out results; the application owns the actions and decides when to show them.

All Ulos widgets, panels and text are required to use Kit components, without manual UI exceptions. Kit-reexported `div`, `v_flex`, and `h_flex` serve layout only; upstream examples permitting custom cells/painting do not override this project policy. Native OS chrome and native picker APIs remain platform-owned, not a bespoke GTK/Swift application UI. Options remains a Kit modal; the requested native-window workflow applies to Add and download status.

### Lag analysis: source evidence, not a runtime benchmark

The locked `gpui-component` 0.7.3 source (`src/dialog/dialog.rs`) sets the default dialog entrance duration to 0.25 seconds and applies slide-down/fade-in animation. This is a dependency configuration observation, not measured Ulos opening latency. Native Add/status windows no longer traverse that modal entrance. The previous eager all-row widget construction is replaced by Kit DataTable viewport cells. Transfer watch polls remain 100ms but apply changed values; the heartbeat refreshes only for changed/stale rates, and unchanged status snapshots do not notify. The 500-record regression covers viewport cell construction and zero manager-model notifications from child opening/typing; native focus and forced test redraws are distinguished from queue notifications. Isolated macOS smoke observations measured synchronous window construction, not visible first paint. No instant-response guarantee or FPS result is established; details and platform limits are recorded in [Status](STATUS.md).

## Desktop reference and clipboard boundary

The light IDM 6.28 reference supplies the manager structure, superseding the earlier dark AB screenshot: native titlebar, menus, action toolbar, navigation, table, and transfer details. The latest user adjustment asks for a stock Kit/shadcn-style grouped collapsible sidebar, replacing the category tree with flat Downloads and File types groups. The newer user request puts macOS menus in the system menu bar through Kit `Menu`/`MenuItem`; other platforms retain Kit in-window dropdowns without search in the menu line. One shared stock action Toolbar uses icon-only Buttons except Add New and places stock search Input on that same row. It guides original GPUI Kit composition, not copied source/branding or a pixel-identical skin. Kit theme and native platform chrome necessarily differ by OS. Stock Light/Dark `Theme::change` replaces the former custom font, blue palette, and radius overrides; do not treat historical reference values as current control styling or promise an exact platform font size. Default controls remain unmodified, including child/status views, with stock Lucide icons registered through `AllAssets`.

The current manager uses GPUI's normal asynchronous clipboard API, behind an off-by-default session Options toggle. Eligibility checks run once per second only while the main window is active, no Add/status window is open, and Options is closed, with eligibility rechecked after async reads; disabled detection does not read the clipboard. Accept a single bounded HTTP/HTTPS URL and prefill confirmation without networking; retain fingerprints rather than non-URL text and do not log clipboard contents. Signed source/query values still exist in memory for an accepted download. Wayland access depends on compositor/provider behavior and requires native testing, as do native folder/save pickers. Naming is pure URL-path processing, not HEAD or Content-Disposition discovery.

## Browser integration references

- [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)
- [Firefox native messaging](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Native_messaging)

Use browser-native host registration, extension identity allowlists, and length-prefixed JSON messaging over standard input/output. Host diagnostic logging must not corrupt the protocol stream. Chromium uses `allowed_origins`; Firefox uses `allowed_extensions`. Registration, message limits, permissions, and installation paths differ by browser/OS and must be checked against the chosen targets. Native messaging alone does not provide automatic download interception or access to browser authentication state.

## HTTP and Rust references

- [MDN: HTTP range requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests)
- [MDN: If-Range](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Range)
- [reqwest documentation](https://docs.rs/reqwest/latest/reqwest/)
- [reqwest response API](https://docs.rs/reqwest/latest/reqwest/struct.Response.html)
- [Tokio documentation](https://docs.rs/tokio/latest/tokio/)

A range advertisement is not sufficient evidence of usable range support. Verify the actual response and representation before writing resumed or segmented bytes. Strong validators and `If-Range` protect against appending a different representation; A full `200` must never be appended to resumed bytes. The current controlled session fails an unexpected If-Range `200`; any future durable recovery must make a separate explicit safe-restart decision. Keep content decoding and byte offsets consistent.

The selected networking direction is async reqwest with rustls and Tokio. Reqwest offers streaming response APIs; feature selection must enable the needed TLS/body behavior without buffering the full download. Its `latest` documentation is mutable: verify APIs and feature names against the version actually selected by the workspace.

## Torrent engine and packaging sources

The default v1 path selects **librqbit 9.0.1**, reviewed for its embedding API, feature flags, runtime ownership and Apache-2.0 licensing. The next-build v2/hybrid/consented advanced-v1 path uses a separate BSD-3-Clause **libtorrent 2** native process. These are source/API references, not evidence of executed tests, native launches or distribution certification:

- [Pinned crate documentation](https://docs.rs/librqbit/9.0.1/librqbit/), [SessionOptions](https://docs.rs/librqbit/9.0.1/librqbit/struct.SessionOptions.html), [AddTorrentOptions](https://docs.rs/librqbit/9.0.1/librqbit/struct.AddTorrentOptions.html) and [crate features](https://docs.rs/crate/librqbit/9.0.1/features): review upload denial, discovery/listener options, persistence and shutdown separately. Ulos disables defaults and enables `rust-tls` / `disable-upload`; runtime session policy also denies payload upload. Optional capability code in the dependency graph does not mean Ulos enables DHT/LSD/UPnP.
- [Engine source](https://github.com/ikatson/rqbit), [pinned crate source](https://docs.rs/crate/librqbit/9.0.1/source/) and [upstream Apache-2.0 license](https://github.com/ikatson/rqbit/blob/main/LICENSE): engine selection does not change Ulos's MIT license. Retain repository `LICENSE`, `THIRD_PARTY_NOTICES.md` and `packaging/licenses/Apache-2.0.txt`; audit transitive obligations before release. Mutable upstream branches are not version-lock evidence.
- [BEP 3](https://www.bittorrent.org/beps/bep_0003.html) and [BEP 52](https://www.bittorrent.org/beps/bep_0052.html): v1 piece SHA-1/infohash identity differs from pure-v2 semantics and HTTP validators. The next-build parser accepts bounded v1, BEP 52 v2 file trees/piece layers and matching hybrids, with separately validated explicit magnet metadata resolution, but not webseeds; see [Torrent contract](TORRENTS.md). Tracker query preservation is necessary for signed/private trackers, but their values must not reach logs/history. Upload-disabled swarms can stall.
- [libtorrent BitTorrent v2](https://libtorrent.org/upgrade_to_2.0-ref.html), [settings](https://libtorrent.org/reference-Settings.html), [session](https://libtorrent.org/reference-Session.html) and [upstream license](https://github.com/arvidn/libtorrent/blob/master/LICENSE): use the major-2 API for BEP 52 rather than inferring v2 from a v1-client flag. Hard no-upload is not guaranteed by this payload worker; zero upload limit means unlimited, not denial, and upload mode is not a substitute. The source requires explicit upload consent, keeps private DHT/PEX and all local discovery/port mapping off, and synchronously tears down the session before the parent independently verifies/publishes. Upstream support is not Ulos runtime evidence.
- [BEP 9 metadata exchange](https://www.bittorrent.org/beps/bep_0009.html) and [BEP 52](https://www.bittorrent.org/beps/bep_0052.html) distinguish magnet identity/metadata from payload approval. The explicit native resolver uses zero priorities/`upload_mode`, default-off separately disclosed public DHT and exact requested-hash/core-parser validation. BEP 9 does not carry required top-level v2 piece layers, so v2/hybrid files larger than one piece fail closed to `.torrent` intake rather than inventing proof layers. This is an implemented contract, not a report of public-swarm or six-platform success.
- [BEP 52](https://www.bittorrent.org/beps/bep_0052.html) defines SHA-256 Merkle trees, piece layers, per-file alignment and hybrid identity; the Rust parent checks roots/layers, agrees on real manifests and verifies both v2 roots and hybrid SHA-1 streams with virtual-zero v1 padding. Legacy v1 SHA-1 identity is preserved. No trusted resume data or general webseed intake is introduced.
- [Pinned vcpkg baseline](https://github.com/microsoft/vcpkg/tree/3cd21e48a75f67acfef289da52893ce79144aaa1/ports/libtorrent) supplies libtorrent 2.1.2 for Windows static triplets. `core,deprfun` avoids default WebTorrent dependencies while retaining ABI 2. CMake finds libtorrent 2 (2.0.15 API baseline); local Homebrew installation is 2.1.2. This version observation does not certify all future 2.x ABI variants. macOS/Homebrew and Linux use system-provided libtorrent 2 packages (local Homebrew 2.1.2 versus Linux 2.0.x), not a common exact-version pin. No GPL torrent engine is selected; supplied `packaging/licenses/` files retain libtorrent BSD and full component notices, OpenSSL Apache-2.0, Boost-1.0 and nlohmann-json MIT alongside Ulos MIT/rqbit Apache notices. These files do not certify a complete transitive audit for every build. Binary relocation does not establish license compliance automatically.
- [GitHub hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) and [Windows ARM64 image inventory](https://github.com/actions/runner-images/blob/main/images/windows/Windows11-Arm64-Readme.md) document `windows-11-arm` / `ubuntu-24.04-arm` availability and native tooling. The workflows select native ARM64 MSVC and CMake generator/platform/host, check exact Rust host/target equality and inspect packaged binary headers. These sources and synthetic header checks establish configuration intent, not successful Windows/Linux ARM engine, CLI or GUI execution. SDK/OS permission checks are not bypassed; six future artifacts are not retroactive release assets.
- [Apple document types/roles/handler rank](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/CoreFoundationKeys.html), [imported UTI declarations](https://developer.apple.com/documentation/bundleresources/information-property-list/utimportedtypedeclarations) and [existing Transmission torrent identifier reference](https://github.com/transmission/transmission/blob/main/macosx/Info.plist): `packaging/macos/Info.plist` imports the existing torrent UTI as Viewer/Alternate, not Owner. `scripts/bundle-macos.sh` copies a local `.app` with an ad-hoc integrity signature, without installing, registering, Developer ID signing, notarizing, launching or changing defaults.
- [freedesktop Exec file arguments](https://specifications.freedesktop.org/desktop-entry-spec/latest/exec-variables.html): Linux's desktop entry uses `%F` for local files and advertises an Open With choice; it is not automatically installed or made default.
- [Microsoft OpenWithProgids](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-include-an-application-on-the-open-with-dialog-box) and [registered application capabilities](https://learn.microsoft.com/en-us/windows/win32/shell/default-programs): the explicit Windows script registers HKCU choices only, never UserChoice/defaults. ## System appearance

Checked against [Kit Theme](https://gpui-kit.com/component/theme) and the pinned Kit 0.7.3 / GPUI 0.3.9 APIs on 2026-10-14. Kit’s stock theme is Light or Dark; `Theme::change` refreshes every window. `Theme::sync_system_appearance` can resolve a window’s current appearance but does not store a three-way application preference. Ulos therefore keeps System/Light/Dark preference separately, clears native application overrides when returning to System, and retains `observe_window_appearance` subscriptions in each native window. Manual choices use the public application appearance override; all component colors remain stock Kit theme tokens. Appearance notification delivery is platform-dependent and is not inferred from handler tests.


## Advanced transfer and completion references

The following primary references support future review. Links are provided without claiming they were fetched or freshly verified during this docs-only edit. These summaries are original prose, not copied implementation examples or IDM source.

- [MDN HTTP range requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests), [If-Range](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Range), [Content-Range](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Range), and [ETag](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/ETag): distinguish actual partial responses from advertised support, validators from weak identity hints, and full-response fallback from safe range continuation. Ulos requires verified `206`, identity encoding, exact ranges/effective URL and a strong ETag; an unexpected If-Range `200` fails the current session rather than appending or silently restarting.
- [tempfile TempPath](https://docs.rs/tempfile/latest/tempfile/struct.TempPath.html): review no-clobber persistence separately from explicit replacement persistence, including platform implementations and races. Ulos Reject/Rename use no-clobber; consent-gated Overwrite publishes successful unique staging. No platform filesystem guarantee is inferred from documentation alone.
- [Kit Progress](https://gpui-kit.com/component/progress), [Tabs](https://gpui-kit.com/component/tabs), and [Label](https://gpui-kit.com/component/label): use the pinned stock components for segmented Status/Speed/Completion navigation and percentage overlay in a shared footer. Wrappers perform layout only; no custom bar/tab painting or Button/Input/Checkbox styling. Native screenshot and accessibility review remain separate.
- [Apple Mac Automation Scripting Guide](https://developer.apple.com/library/archive/documentation/LanguagesUtilities/Conceptual/MacAutomationScriptingGuide/) and [Apple Automation privacy controls](https://support.apple.com/guide/mac-help/allow-apps-to-automate-and-control-other-apps-mchl108e1718/mac): System Events scripting and Automation authorization remain OS-controlled. The production provider requests shutdown via osascript; it does not bypass permissions or force other apps closed.
- [systemctl manual](https://www.freedesktop.org/software/systemd/man/latest/systemctl.html): `poweroff` requests OS shutdown; systemd/provider presence and operator permission must be established on the actual Linux host. Ulos does not invoke sudo or install systemd.
- [Microsoft shutdown command](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shutdown): the production Windows plan selects shutdown (`/s`) with zero delay (`/t 0`), without `/f` or elevation. Command-plan inspection is not observed poweroff or application-close validation.

The limiter charges aggregate output consumption before writes across range workers; transport prefetch and probe bytes prevent a strict wire-speed/QoS claim. Session pause closes responses and preserves written offsets only in memory; durable identity/checkpoint recovery remains research and future implementation. Source/API observations do not demonstrate speed improvements.

Poweroff is a consequential production action, not cosmetic completion status. Keep default-off confirmed per-download intent, save-all-work warning, visible cancellable countdown and final live-window/all-finished gate. Tests inspect plans and suppress dispatch; no actual host shutdown, OS settings change or native poweroff validation is reported. Successful provider exit must be recorded separately from observed power state. These HTTP/completion contracts do not require copied third-party code; Ulos retains MIT and dependency licenses remain independent.

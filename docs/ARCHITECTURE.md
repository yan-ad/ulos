# Architecture

Updated: 2026-10-14. Current HTTP structure and future design are distinguished below; [Status](STATUS.md) records verification.

## Workspace and dependency boundaries

| Crate | Responsibility | Dependencies/direction |
| --- | --- | --- |
| `crates/ulos-core` | Legacy single-stream HTTP plus controlled range transfers, live controls, and safe file lifecycle | Tokio; reqwest with rustls; no GPUI dependency |
| `crates/ulos-cli` | Parse URL/output arguments, invoke core, report outcome and exit status | Depends on core |
| `crates/ulos-desktop` | Session manager and single-active-transfer HTTP orchestration | GPUI Kit; adapter to shared core task |

Configure core and CLI as workspace default members so ordinary checks do not require GUI platform dependencies. Networking and filesystem work must remain outside the UI render path. Desktop integration uses an owned async runtime and task state rather than making core depend on GPUI entities.

## HTTP task orchestration

`ulos-core/src/http.rs` owns the HTTP implementation; `lib.rs` re-exports its public API and declares modules. `tasks.rs` supplies `HttpDownloadTask::start` on a caller-supplied Tokio runtime handle, orchestrating preparation and download. A bounded, coalescing watch channel exposes `TransferState`: `Preparing`, `Downloading`, `Paused`, `Completed`, `Failed`, and `Cancelled`. It is latest-state delivery, not a lossless progress-event log. A terminal guard reports a generic failure on worker unwind without publishing panic text. Dropping the task requests cancellation without awaiting termination; it is not proof that publication or cleanup has finished. CLI and desktop share the task facade, not the same engine path: legacy `start` invokes `http.rs`/`Downloader`; desktop `start_with_options` invokes `transfer.rs` and exposes control/telemetry watches.

Desktop `main.rs` registers Kit `AllAssets`, initializes System-default stock theme, opens a native-titlebar manager window (minimum 880 × 540 logical pixels), installs macOS native menus, binds Add URL, and owns the Tokio runtime with a two-second shutdown timeout. A timeout does not establish successful cleanup. `manager.rs` owns the active `HttpDownloadTask`, retained input/table entities and weak child-window registries, subscriptions, and GPUI observer tasks. Observations are guarded by active download ID so stale transfers cannot mutate a newer item. Terminal observations defer queue advancement until the current observer returns; the observer polls coalesced state at 100ms intervals, applying only changed watch values (plus the initial value). The heartbeat refreshes/notifies only when the measured rate changes, including expiry of stale rates. Network/filesystem work stays off the render path.

## Desktop manager modules and contracts

- `queue.rs`: pure presentation/session model with stable monotonic IDs, a 500-record cap, private source URLs, destination-derived categories, selection, search, and sorting. Waiting dispatch uses explicit `(queue_order, id)`, never visible order. Lexical duplicate destinations are rejected for queued/active items; this is not filesystem-alias detection. Core publication policy is the final safety boundary: Reject/Rename are no-clobber; Overwrite is explicit and consent-gated by the desktop. SQLite stores metadata-only destination/status/bytes history, not source URLs or schedules. Restored source-less records cannot start or retry. Queue names, membership, ordering, schedules, descriptions, and Last try are session-only; this is not durable transfer recovery.
- `manager.rs`: one active transfer, queue start/stop, cancellation, record removal, finished-file reveal, clipboard proposals, and live Details snapshots. Stop Queue leaves current work running; Stop All also requests cancellation. Start download starts the chosen item when idle (not necessarily the oldest queued item), or enables queue advancement when busy. Subsequent advancement selects minimum `(queue_order, id)` among waiting candidates in all running queues; paused work retains the global active slot. Main-toolbar Start/Stop Queue targets Main queue, named queues use Scheduler, and Stop All stops every queue and cancels active work. Download later does not enable a stopped queue; existing running advancement still applies.
- `manager_render.rs` / `palette.rs`: native-titlebar structure with macOS menus outside the window; non-macOS keeps Kit dropdowns without search in the menu line. A shared Toolbar contains stock Buttons (icon-only except Add URL) with accessible labels and built-in tooltips; stock search Input shares that row in a 240px, 160px-minimum shrinkable layout wrapper. `Toolbar::content` avoids `child` preparation that changes control size/variant. Grouped collapsible Sidebar, viewport DataTable, Empty, Label, and StatusBar remain Kit components. DataTable uses public `with_size(Size::Size(px(36.)))`, `header_row_height(px(32.))`, and `bordered(false)`; filenames are Kit Links, not Buttons. Compact borderless geometry avoids decorative framing. `palette.rs` stores the session-only System/Light/Dark preference separately from effective appearance. System clears the application appearance override and follows retained per-window appearance observers; manual choices set the override and use stock `Theme::change`. No custom font/color/radius palette. Manager and child Buttons/Inputs/Checkboxes have no per-control styling overrides. Sorting/filtering/search do not change scheduling; Scheduler opens a native child; Grabber remains disabled with an explanatory tooltip.
- `native_menu.rs`: macOS Kit `Menu`/`MenuItem` integration supplies Ulos / Tasks / File / Edit / Downloads / View / Help, typed actions, enabled-state snapshots and checked filter/theme items. Application callbacks hold weak manager owners, validate current state both before deferred dispatch and at execution, and enter the active window only after the current update to avoid reentrancy. A surviving child can route commands after main close; Options uses only the main handle and requires a live main window with no child/dialog conflict. Global shortcuts are secondary-N/comma/Q (⌘N/⌘,/⌘Q on macOS). Edit uses Kit input Undo/Redo/Cut/Copy/Paste/SelectAll actions through the focused responder path, not manager clipboard handlers.
- `add_download.rs`: retained Address / File name / Save as inputs, native folder and save prompts, manual-name preservation, and sanitized destination submission. Prompts disable editing/dismissal while outstanding. They are platform pickers in the owning child window, not bespoke GTK/Swift UI. Add and status use independent native windows; Options remains a Kit modal in the manager window.
- Core `naming.rs`: pure URL-path suggestion and portable component sanitization, with no HEAD or Content-Disposition request. Percent decoding is UTF-8-lossy; query/fragment never contribute to a name. Replace separators, controls, bidi formatting, and unsafe Windows punctuation; trim leading/trailing spaces/dots; protect reserved device bases including COM1–9/LPT1–9 and superscript ¹/²/³ variants. Bound names to 180 UTF-8 bytes on character boundaries, preserving a short extension when possible. Selected/edited filenames are also sanitized. Case/Unicode spelling is preserved, but normalization, filesystem equivalence, collision avoidance, and successful publication are not implied.
- `download_details.rs`: passive snapshot view with persistent tab/disclosure state, composed from Kit GroupBox, DescriptionList, Label, Table, Tabs, Progress/Spinner, Button, and Toolbar. Identical snapshots do not notify. It never starts I/O; Cancel emits a parent-owned cancellation request. Unknown/zero totals do not invent percentages. Actual per-connection telemetry supplies rows, with no invented segments for queued items. Pause/Resume is available only for verified range sessions. Retained Speed inputs emit validated parent-owned live rate/next-start connection changes; Completion emits intent for parent confirmation and displays gate/countdown state. A shared progress footer is visible on all tabs. Rates use real byte/time observations and expire when stale; ETA requires a known total and usable rate.
- `clipboard.rs`: detector retains only a text fingerprint, not non-URL content. Options opt-in is session-only and off by default. A one-second GPUI timer checks main-window activation and all Add/status/Scheduler/Options state before `read_from_clipboard_async`; disabled/inactive/child-window-open/Options-open states perform no reads, and proposal delivery rechecks eligibility. Only one trimmed HTTP/HTTPS URL, no embedded credentials or internal whitespace, within 16 KiB is accepted. Repeated fingerprints suppress reopened proposals. GPUI may read clipboard contents before the application-level size rejection; the limit bounds accepted candidates, not an OS clipboard allocation guarantee. Wayland behavior depends on the compositor. There is no proposal-triggered network request or automatic download.

Accepted source URLs, including signed query values, are retained in actual task/session memory for downloads. Source-bearing models deliberately avoid Debug; Details snapshots remove query/fragment/credentials. This is not a claim that application memory contains no secrets. No clipboard contents or network secrets are logged; sources are not persisted in metadata history.

## Sidebar presentation and actions

`manager_render.rs` composes a stock `Sidebar` with `SidebarCollapsible::Icon` and two `SidebarGroup`s. Downloads contains All downloads / Finished / Unfinished / Queue. File types renders the seven `Category::ALL` entries as flat items (Image, Music, Video, Apps, Document, Compressed, Other), not children of All downloads. Counts come from the queue model via Kit Label suffixes; item accessible names include the count. Stock collapsed rendering hides labels/suffixes and supplies icon-rail tooltips.

`DownloadManager::sidebar_collapsed` starts false and is not persisted. `toggle_sidebar` flips it and notifies the view without `sync_table`; queue records, selected IDs, filter, search, explicit dispatch order, and HTTP orchestration are unchanged. Kit owns the default 255px/48px widths and 200ms transition. A stock Button with `PanelLeftClose` / `PanelLeftOpen`, tooltip, and accessible name sits immediately before Add URL in `Toolbar::content`. `SidebarToggleButton` is intentionally unused because it forces ghost/small styling. The existing TitleBar/full-content native chrome and traffic lights remain unchanged.

`main.rs` binds secondary-B (⌘B / Ctrl+B) to `ToggleSidebar` in the `DownloadManager` context; it is not a child-global key binding. macOS `native_menu.rs` routes global typed `ToggleDownloadsSidebar` through `Command::ToggleSidebar`, including from a child, and derives Collapse Sidebar / Expand Sidebar from manager state. Non-macOS keeps its in-window View Toggle sidebar command. This shortcut/menu wiring is not proof of full sidebar item keyboard navigation or native accessibility.

## Native window ownership and table rendering

`window_chrome.rs` configures the main window. On macOS, transparent full-content native titlebar options remove the separate title strip; Kit `TitleBar` wraps the action Toolbar and owns dragging. Native traffic lights remain, with reserved layout space and a titlebar-position option. Window metadata still names Ulos. Add uses native decorations with no title text; status and non-macOS decorations otherwise retain their existing behavior. macOS status uses transparent full-content chrome, a fixed Download title, and a Kit TitleBar containing segmented Status/Speed/Completion tabs. Stock Button/Input/Checkbox appearance is unaffected.

`native_windows.rs` opens each child through `gpui_kit::open_window`, which supplies an independent Kit Root. `NativeAddWindow`, `StatusWindow`, and `NativeSchedulerWindow` own their content entities, a strong handle to `DownloadManager`, and child-context subscriptions. The manager is currently a transitional shared view/model owner, not a separately extracted session-service entity. Closing the main window therefore leaves queue/transfer state alive while a child root owns it; an Add submission can hand ownership to a newly opened status window even after main close. Status close leaves the transfer running but cancels its shutdown intent/countdown; explicit Cancel targets only its download ID. `main.rs` requests quit only when the last native window closes, then uses the existing two-second runtime shutdown timeout, not a guarantee of completed cleanup.

Add windows are keyed by WindowId: every invocation creates a new independent draft, capped at 16 live Add windows. Status windows are keyed by DownloadId: reopening reuses/activates the same native window, while different IDs can coexist. Registries hold window handles and weak content entities, avoiding a strong manager/child cycle. Closed-window callbacks remove entries; opening prunes stale Add entries and replaces stale status entries. Removing/clearing session records closes only their related status roots; file contents remain untouched. Native close requests and explicit dismissal/submission are blocked while an Add path picker is outstanding.

`download_table.rs` owns presentation snapshots in `TableState<DownloadTable>`; Kit DataTable instantiates viewport cell controls instead of an eager widget tree for all 500 records. Queue changes, search/filter/sort/selection, transfer states, and changed or stale rates refresh snapshots. Checkbox selection belongs to stable queue IDs; table row events resolve the current snapshot index to an ID. Name/size header sorting is deferred until the table delegate borrow ends, then resets snapshots without changing explicit dispatch order. Kit positional highlight/navigation state is distinct from record checkbox selection; native keyboard behavior across sorting/filtering still needs review.

Opening Add/status changes no queue presentation and has no explicit manager notification. A separate `MenuStateChanged` event refreshes cached native-menu metadata when children open; manager observation covers ordinary state changes, global Theme and preference observation cover System/Light/Dark changes, and deferred close observation refreshes lifecycle state. `set_menus` runs only when the snapshot changes; menu-only refresh does not call manager `notify`. The 500-record render-counter regression allows one focus redraw on opening but no manager/table-cell rebuild for child typing. These are structural checks, not native latency/FPS measurements. Options still uses Kit Dialog; Add/status bypass its default modal entrance animation. All controls, panels, and text must use Kit components, with Kit-reexported `div`/`v_flex`/`h_flex` reserved for layout and no custom painting.

## Session scheduler and table metadata

`scheduler.rs` is a pure local-clock model: at most 32 named queues including default Main queue, unique validated names, once/weekly specs, and monotonic occurrence-consumption watermarks. Once starts must be future; Weekly needs at least one weekday. UI parsing in `scheduler_window.rs` requires `YYYY-MM-DD` and 24-hour `HH:MM`, with optional unequal stop; an earlier stop belongs to the next day. Local gaps skip the occurrence; folds choose the earlier instant for start and stop. Wake catches only a current unexpired window, never an ended one; no-stop catch-up ends at the start's local calendar-day boundary, without stopping an already-started queue. Repeated ticks, clock rollback, manual stop, and terminal rows cannot replay an occurrence or cause automatic retries.

`manager_scheduler.rs` snapshots queue members in `(queue_order, id)` order, revalidates child requests, assigns main-table checkbox selections, reorders only waiting members, and reassigns a deleted non-main queue's members to Main. Active/paused membership cannot move and blocks deletion. Start/stop actions control advancement, not parallel ownership; scheduled/manual queue stop lets active work finish. A single manager-owned HTTP task arbitrates all running queues by minimum `(queue_order, id)`. Schedule enablement cancels shutdown and blocks its confirmation/countdown/final dispatch gates. Tick processing consumes expired occurrences even when file removal blocks dispatch.

The Scheduler's native child is reused/activated, owns an independent Kit Root and strong shared manager handle, and survives main close. Both clipboard-read eligibility and async proposal delivery exclude Scheduler. No OS scheduler is registered. Queue names, membership/order, schedules, descriptions, and Last try live only in session memory; SQLite history does not establish durable recovery.

`download_table.rs` has nine columns total: checkbox, Name, Size, Status, Transfer rate, Queue, Time left, Last try, Description. Stable-ID checkbox selection is independent of row focus; filename Link, Enter on the focused row, and row double-click open Details. Name retains its colored category icon with no Button styling override. Time left derives only from actual rate and known remaining bytes; Last try records actual worker start and renders local time; Description is explicit Scheduler user input. Missing values stay blank, never fabricated metadata. Sorting remains presentation-only.

## Legacy HTTP transfer contract (CLI)

1. Validate a parseable HTTP/HTTPS URL and usable output path. Reject unsupported schemes and invalid requests before creating a file. Recheck allowed schemes across redirects; preserve normal TLS certificate validation.
2. Require an acceptable full-response HTTP status. The initial downloader requests a full representation, not a range, and must not treat an unsolicited partial response as a complete file.
3. Create a unique `.part` staging file with exclusive creation. Never truncate a pre-existing final or staging file. A collision must produce a new candidate or a clear error, not an overwrite.
4. Stream response chunks to disk with bounded memory; do not accumulate the response in memory. Count bytes written and compare with the applicable expected body length when available. Unknown length is allowed but cannot provide a length-match guarantee. Content decoding must not cause comparison against a different representation's length.
5. Flush/close the successful transfer and publish it without replacing an existing destination. A check followed by an ordinary overwrite-capable rename is not sufficient: use a no-clobber publication strategy and handle a destination appearing during transfer.
6. On network, length, or filesystem failure, close and remove only staging files owned by this operation. The scaffold uses best-effort temporary-file cleanup; cleanup-error reporting is future work. Abrupt process termination can leave staging files; crash recovery is future work.

File creation and publication execute on blocking workers rather than the async task. Publication checks a cancellation flag before starting, but a filesystem publication already in progress can finish after cancellation. The CLI reports that possibility explicitly. A stronger cancellation/commit model is part of milestone 2, not a scaffold guarantee. Automatic redirect referers are disabled to avoid leaking signed query strings to another origin.

Neither engine has a checkpoint store or crash-resumable partial-file contract. The controlled desktop engine supports session pause/resume only. Do not retain failed partial files under a claim that they can be resumed. Desktop filename sanitization prevents suggestions/edited names from becoming path components; the core/CLI explicit output contract does not trust server-supplied names.

## Durable persistence and resume: future design

SQLite destination/status/bytes history exists, but excludes sources and scheduler metadata. Restored source-less records cannot start/retry. Durable source-bearing queues and checkpoints remain future work. A proposed model stores transfer identity, destination/staging path, state, selected representation metadata, and verified byte offsets. Database updates and file durability need a documented recovery protocol; a row alone does not prove bytes survived a crash.

Resume must verify actual server behavior, not just `Accept-Ranges`. For a saved offset, send `Range` with a suitable `If-Range` validator. Prefer a stored strong ETag; a weak ETag is insufficient for strong representation identity. Validate `206`, `Content-Range` start/end/total, body length, and representation/encoding consistency before appending. For future durable recovery, a `200` requires an explicit safe-restart decision, never append it to old bytes. The current controlled session instead fails unexpected If-Range `200` and changed resources without automatic restart. Changed validators, inconsistent ranges, and `416` require explicit recovery rules rather than assuming completion. Without trustworthy representation identity, restart instead of claiming a safe resume.

Controlled session segmentation and aggregate limiting are implemented as described below; durable segmentation recovery remains future work. Bound connections, buffering, retries, and aggregate rate, verify each response and final coverage, and never advertise an unmeasured speed benefit.

## Torrent boundary: future design

Torrent support is planned, not implemented. HTTP already has a concrete core module; a future torrent engine will have a separate module while keeping orchestration independent of GPUI. Do not introduce a root generic backend trait before a concrete second backend establishes the shared contract.

A separate core torrent module/engine would validate magnet or `.torrent` sources, bound metadata parsing, enforce safe multifile destinations with no overwrites, and verify piece hashes. An infohash identifies torrent metadata; it is not a strong single-file HTTP representation validator and must not be substituted for an ETag/`If-Range` contract. When source-bearing persistence arrives, store protocol-tagged source data rather than treating every source as an HTTP URL. Tracker/DHT privacy, seeding, bandwidth, and storage policy remain decisions. See [Torrent scope](TORRENTS.md) for research and acceptance boundaries.

## Browser bridge: future design

A small JS/TS extension will communicate through browser-native messaging to a Rust host, which validates input and hands explicit requests to the application/core. Chromium and Firefox have different host registration/allowlist rules. Use a versioned, bounded message schema and validate allowed extension identity, URLs, paths, and user intent. Keep browser secrets out of logs; authenticated URL/header handling remains an unresolved design requirement. Do not expose an unauthenticated network listener as a substitute for native messaging.

## Platform boundary

Use GPUI Kit's aligned dependency set rather than independently overriding GPUI snapshots. Linux needs a graphical X11/Wayland session and a working Vulkan driver. Platform packaging, runtime shutdown, UI accessibility, and filesystem publication semantics need platform-specific verification. See [Research](RESEARCH.md) and [Testing](TESTING.md).

### Appearance preference

The toolbar uses a stock Kit Button/DropdownMenu with Monitor, Sun, or Moon icons for the selected preference and three checked choices. Native and fallback View menus expose the same three modes. Each manager/Add/status/Scheduler native window retains an appearance subscription; System callbacks refresh all Kit windows when the effective mode changes, while manual overrides ignore those callbacks. The selected preference—not effective dark/light colors—determines menu checkmarks. A preference-global observation updates native menu metadata even when selecting System leaves the effective palette unchanged. Selection is session-only; startup always returns to System.


## Controlled desktop transfer contract

`ulos-core/src/transfer.rs` owns `TransferOptions`, `TransferControl`, range workers, telemetry, one aggregate limiter, and publication. `tasks.rs::HttpDownloadTask::start_with_options` runs it on the caller runtime, exposing coalesced state and telemetry watches. Legacy `start` and CLI behavior remain single-stream/no-overwrite. Core options default to one connection; the desktop explicitly selects four. Valid counts are 1–8, with Add choices 1/2/4/8. A positive optional byte rate is supported; `None` is unlimited. Desktop whole-number input accepts 1–1,048,576 KiB/s with checked conversion.

1. Validate URL/options and inspect the destination on the worker before networking. Default Reject fails if the destination exists, without an HTTP request. Redirect policy preserves HTTP/HTTPS, rejects embedded credentials and HTTPS downgrades, bounds redirects, and disables referers.
2. Create a unique same-directory staging file. Send `Range: bytes=0-0` with `Accept-Encoding: identity`. A valid one-byte `206`, exact Content-Range and strong ETag establish range capability; Accept-Ranges alone does not. Identity encoding is required. An unsupported full `200` is reused once as the full stream. A valid probe with weak/missing ETag falls back to a new full GET, not an appended probe or fabricated parallel capability.
3. Partition known total bytes into non-overlapping bounded ranges; actual count can be less than requested for small files. Every segment, including a resumed segment, uses If-Range and validates `206`, exact Content-Range/total, effective URL, identity encoding, validator and body length before accepting bytes. Unexpected If-Range `200` or changed identity fails: no silent append or automatic restart of a changed resource.
4. One async budget serializes grants across all connections before writing consumed chunks, with no initial burst. Live setting changes interrupt waits; metadata is refreshed by subsequent telemetry callbacks. This limits aggregate output consumption, not bytes already buffered by reqwest/TCP, probe overhead, or wire QoS. No speedup is measured or promised.
5. Pause closes range responses and preserves each worker's written offset in the live session. Resume requests the remaining offset through the same validation contract. A paused active item owns the queue slot; unsupported full streams disable Pause. Failure/cancel drops owned workers and staging with best-effort cleanup. No checkpoints or crash recovery exist.
6. Flush successful staging and publish according to policy. Reject uses `persist_noclobber`. Rename tries the original then sanitized `stem (1).extension` through at most 10,000 numbered candidates, retaining the 180-byte filename bound; a collision at publication retries no-clobber, not a check-then-overwrite. Overwrite rechecks that an existing target is a regular file (not a directory/symlink) and uses tempfile replacement publication: OS rename semantics, including Windows MoveFile replacement. The old file remains on transfer failure. Platform filesystem behavior still requires native tests; ancestor-path aliasing is not a sandbox guarantee.

A filesystem commit already underway may finish after cancellation. A Completed receipt is sent only after successful publication and carries the actual destination, including a numbered result. No source URL or validator is exposed through telemetry; source-bearing state is not Debug/loggable. Details removes URL credentials/query/fragment and sanitizes errors, but path secrets are not automatically hidden.

`manager.rs` applies live rate to the active control and accepted record options; next-start connections are allowed only for queued or inactive failed retry state, not an active or paused context. Add submits an overwrite-consent snapshot; the parent rejects unauthorized Overwrite. Retry Overwrite requires a separate Kit dialog, whereas Rename retries a fresh session. Neither retries automatically.

## Completion provider and parent gate

`ulos-desktop/src/completion.rs` defines default-None `CompletionAction`, a single-use `CompletionGate`, the 30-second countdown, and a production OS provider. Gate operations never run commands. `manager.rs` confirms intent, arms only active eligible work, starts countdown only after published Completed and all records finished, and displays countdown/Cancel through Details. New work/retry, failures/cancellation, removals, status-window close and all-window close cancel intent. `completion_tick` rechecks no active task, all records finished, record existence and the same live status-window handle immediately before consuming the gate. This prevents a hidden countdown while permitting the download to continue after status close.

The production command plans are macOS `/usr/bin/osascript` asking System Events to shut down, Linux available `systemctl poweroff` (absolute standard path or PATH fallback), and Windows `shutdown.exe /s /t 0`. No forced app closure, elevation, sudo or permission bypass. macOS Automation and Linux/Windows permissions remain OS decisions. A successful exit means provider acceptance, not observed poweroff; provider failures are displayed with bounded diagnostics rather than raw potentially sensitive stderr. Once dispatched, cancelling the awaiting future cannot revoke the OS request. Test-build parent dispatch is suppressed, and tests inspect pure plans/gates, never execute power actions. No host shutdown was tested.

## Add draft inspection (2026-10-15)

Address input changes debounce a HEAD-only advisory size request for 450ms. Invalid/credential-bearing URLs schedule no HTTP request; a new edit or native close aborts pending HTTP work and invalidates stale replies. Programmatic/clipboard prefill stays network-free and offers Check size until the user edits the address or explicitly checks it. Preview never starts a transfer, uses GET, writes files, or establishes range/resume support. Display uses decimal KB/MB/GB/TB and the queue's filename-derived category icon/label; a category is not content inspection.

Sanitized target paths are checked after a 150ms debounce on a Tokio blocking worker, not during render. Only an existing regular file exposes the stock Kit collision RadioGroup. Missing targets reset to Reject; directories, symlinks and inspection errors show a warning. This check is advisory, not a publication lock: a target appearing later remains protected by core no-clobber behavior. Path edits reset policy/consent; Overwrite requires a separate checkbox tied to the exact checked path, revalidated by the native parent. Connections use stock Kit RadioGroup (1/2/4/8/16). Add retains native window controls and dragging but has no title text.

Add now requests non-minimizable, non-resizable native decorations through Kit's window options, without changing manager/status capabilities. Kit 0.7.3 has no individual traffic-light visibility API; capability flags do not establish that macOS hides disabled buttons. Native visual validation remains required. The scrollable form and native close/picker guards are retained.

Start, Download later, Enter from either input, and native parent acceptance share a validation gate: valid credential-free HTTP(S) address, usable destination, completed current-path inspection, resolved existing-file policy, and any required replacement consent. Existing-file Reject disables both download actions, not Cancel, Save As, or the radios needed to resolve the conflict. Enter on an incomplete draft displays actionable guidance and focuses a missing Address/Save As field. No deferred automatic start follows a pending destination check. The size/resume advisory footer is removed; metadata remains unverified preview data. Stock Start styling and the destination-specific checkbox remain required by the current project policies.

`file_icons.rs` owns category glyphs and theme-aware icon colors, shared by sidebar, table filename icon, and Add preview. Downloads-group sidebar icons use orange; file categories have distinct shades while preserving labels/glyphs and stock control styling. Contrast tests cover stock Light/Dark background, sidebar, selected/hover, secondary and table surfaces at the 3:1 non-text threshold. This is numeric token verification, not native rendering or screen-reader evidence.

The Add overwrite field keeps its required checkbox but no longer repeats the staged-publication description or authorization paragraph beneath it. `submission_issue` still rejects missing consent; presentation suppresses only that redundant issue because the visible checkbox names the required action. Other validation guidance, destination-bound consent resets, Enter guards, and native parent validation remain unchanged.

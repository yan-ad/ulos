# Shared Address magnet review

Scope: continuation of the existing AddDownload magnet draft. Post-implementation review, as requested in AGENTS.md. This is a source and mounted-test review, not native visual or accessibility certification.

## Direction and decisions

- Keep the existing DESIGN.md download-manager workflow and stock Kit colors, typography and controls; no new branding or assets.
- ENERGY 1 / RHYTHM 1 / MOTION 1: ordered form fields, no new animation or decoration.
- One Address input avoids contradictory source drafts. Torrent review owns its destination and explicit consent; the retained HTTP destination survives switching back.
- Keep Resolve separate from Start and Download later because metadata networking is not payload approval.
- Keep Address and the existing action footer outside the scrollable review so source edits and cancellation remain available.
- Use stock Form, Field, Input, Label, Checkbox, RadioGroup, DescriptionList, GroupBox, Toolbar and Button. Layout helpers provide geometry only; no Button/Input/Checkbox styling overrides.

## Findings requiring native review

1. **HIGH, R-35 / R-34: native visual and theme evidence remains incomplete.** Mounted tests and source inspection do not establish native 560 × 540 clipping, scrolling, first paint, or Light/Dark rendering. Native screenshots and an element-by-element click-through are still needed before calling the GUI complete.
2. **HIGH, R-32 / R-25: native accessibility remains unverified.** No screen-reader, complete focus traversal, native Escape behavior, zoom or contrast certification was performed for the embedded form. Stock Kit widgets preserve their existing implementation but are not proof of these outcomes.

These are verification gaps, not observed rendering or accessibility defects. No speculative visual changes were made. Further fixes require concrete findings and user approval.

## Source and mounted interaction evidence

- Magnet prefill displays Resolve and hides the duplicate torrent-source picker.
- Enter on unresolved metadata emits no payload request; malformed/case-insensitive magnet inputs schedule no HTTP preview worker.
- Download later after fixture-reviewed metadata queues one torrent without starting a stopped queue or opening status.
- The native parent rejects a changed live Address even without InputEvent::Change delivery and rejects forged upload settings.
- A stock Start click after main-window closure opens the status window; the test then cancels the owned transfer.
- An outstanding embedded folder picker vetoes close, prefill, dismissal and submission. Canceling the picker permits normal closure.
- HTTP manual destinations survive HTTP/magnet switches and require a fresh target check on return.
- Address changes abort pending metadata work and reset upload/DHT settings.

Successful resolution in these UI routing tests is explicitly injected parsed fixture metadata, not evidence of real magnet discovery. Real resolver/hash/worker integration remains separate in core. See docs/STATUS.md for exact executed checks and their outcomes.

No invented metrics, decorative panels, new custom controls or assets were introduced. No public swarm, clipboard logging, OS association change, permission change or real shutdown dispatch was used.

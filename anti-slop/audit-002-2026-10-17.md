# Windows command header and download-row menus

Post-implementation review requested by AGENTS.md. Scope: the supplied Windows screenshot, approved underline command tabs, and right-click actions on downloads. Source/mounted adapter evidence is not native Windows visual or accessibility certification.

## Approved direction

- Replace Windows' separate visible Ulos title/icon strip and dropdown command row with one Kit TitleBar containing underline Tasks / File / Downloads / View / Help tabs beside Kit caption controls.
- Tabs select real command sections; they do not imitate dropdown menus. Tasks retains the familiar action toolbar, other sections use stock labeled commands, and search stays available with its existing value.
- Keep window identity in OS metadata. macOS system menus/traffic-light layout and Linux dropdown/native-titlebar presentation remain unchanged.
- Stock Kit typography/colors/control sizing. ENERGY 1 / RHYTHM 1 / MOTION 1: no custom skin, decorative assets or new animation. No Button/Input/Checkbox style or variant overrides; toolbar items use content, not child preparation.
- Use the supported Kit table context-menu hook. Menus target the clicked stable ID without checking it or replacing the checked selection. Keep unavailable actions visibly disabled; revalidate at invocation.

## Findings and fixes

1. **HIGH: underline tabs exceeded the default titlebar height.** Mounted geometry measured a 36px tab partly outside the 34px titlebar. Fixed by giving the TitleBar 40px layout height, without shrinking/restyling tabs, Buttons or caption controls. A regression asserts containment at 880px window width alongside existing command/search non-overlap checks.
2. **HIGH verification gap: native Windows chrome remains unverified.** Local host/target is Apple Silicon macOS. The test harness mounts the same header methods but does not render Windows caption controls. Windows compilation, snap/maximize/restore, tab click versus drag hit testing, double-click, resize borders, Alt+F4, DPI/text scaling and first paint require a Windows run.
3. **HIGH verification gap: complete native keyboard/accessibility review remains unverified.** Mounted menu tests exercise Up/Down/Enter/Escape, but do not prove screen-reader announcements, full keyboard-only right-click invocation, high-contrast behavior or a native theme/contrast pass. No claim that these tasks are complete.

No speculative visual restyling was added for the remaining evidence gaps. Native findings should drive further changes.

## Mounted behavior reviewed

- All five tab clicks expose actual command handlers; shared search text/filter state survives switches.
- Commands and search remain on one row at the 880px minimum width; stock Button heights are retained. Header tabs fit vertically in their container after the height fix.
- Right-clicking an unchecked download and using Down/Enter opens that download's Details, preserving other checked rows.
- Removing through the row menu captures only the clicked ID, even after sort. Confirmation Cancel keeps the record; record-only confirmation removes it without deleting bytes.
- Stale removed targets and blank-table right clicks do not act on the checked row.
- Open-menu actions keep the original ID after filtering hides it; Escape dismisses without queue/selection changes.
- Command gates cover unavailable pause, cancellation in progress, active-record removal, stale retry state and restored source-less history. Context Retry always requests Reject, never old overwrite permission.

These are Kit popups, not native OS context menus. No public API for native platform popups was adopted, and no bespoke platform UI or dependency source was copied. Transfer/file-publication logic is unchanged. Exact test/build/lint outcomes and ignored-test accounting belong to docs/STATUS.md.

# Ulos desktop manager foundation

The light IDM 6.28 reference supplies the working manager structure, superseding the earlier dark AB Download Manager reference. The latest sidebar request refines it to stock Kit/shadcn-style grouped navigation with an icon-mode collapse toggle. Interpret the reference as a layout/workflow request, not inferred branding, source reuse, or a promise of pixel-identical rendering. Native platform chrome and GPUI Kit styles differ across operating systems.

Updated: 2026-10-14.

## Implemented direction

- Native titlebar. On macOS, Ulos / Tasks / File / Edit / Downloads / View / Help are native system-menu-bar menus via Kit `Menu` / `MenuItem`, not an in-window strip. Other platforms retain in-window Tasks / File / Downloads / View / Help Kit dropdowns; search is not in that menu line.
- One shared compact action Toolbar: stock icon-only Buttons except labeled Add New, with accessible names and Kit `Button::tooltip`. The stock search Input occupies the same row in a shrinkable 240px wrapper (160px minimum), with no custom Input style. Grouped collapsible sidebar, table, and session status bar. The table has ten columns total: selection checkbox, Name, Size, Status, Transfer rate, Queue, Time left, Last try, Description, and Type. Checkbox selection is independent of focused-row highlight. Name/size sorting and filename search affect presentation only.
- Follow system appearance by default; the stock toolbar theme selector and View menu offer System, Light, and Dark. Manual overrides stay fixed while System follows appearance changes through retained window observers and stock `Theme::change`. The reference supplies structure, not a custom skin: the former 13px font, blue palette, and 2px radii prescriptions are removed. Fonts, colors, radii, and controls follow Kit theme defaults rather than an asserted OS-independent font size. DataTable uses public Kit APIs for borderless 36px rows and a 32px header (`bordered(false)`, `with_size`, `header_row_height`). Compact rows and no rounded outer border keep attention on actual download metadata, without decorative framing. Filename cells use stock Kit Links with colored category icons, not Button variants.
- Use GPUI Kit for every application widget, with no manual UI exceptions: Toolbar, StatusBar, Label, GroupBox, DescriptionList, Empty, DataTable, Form/Input, Button, Checkbox, Tabs, Progress, Spinner, Sidebar, menus, Dialog, and Icons as appropriate. `div`, `v_flex`, and `h_flex` reexported by Kit are allowed only for layout, not hand-built controls, text labels, or panels. No custom painting, browser/webview, bespoke GTK/Swift desktop UI, copied logos/artwork, or reference screenshot filenames as sample downloads.
- Empty tables are honest. The real session queue is capped at 500 records and runs one HTTP or torrent transfer at a time. Explicit dispatch order is independent of categories, filtering, search, and sort. Selection uses stable IDs.
- Add a download in an independent native window: each invocation opens a new draft (maximum 16 concurrently). Address, File name, Save as, Choose folder / Save as pickers, Start download / Download later. Preserve manually chosen names when the address changes; sanitize both suggestions and selected/edited filenames. Reject existing destinations by default. Rename publishes a numbered filename; explicit Overwrite requires destination-specific consent and successful staging.
- Click a filename Link, press Enter on the focused row, double-click a row, or choose Details for a native status window. One window per download is reused and activated on reopening; different download IDs can be viewed concurrently. Options remains a Kit modal; the separate-window requirement covers Add and status, not every dialog; Scheduler is also a native child. Status shows real bytes and available rate/ETA; unknown values stay unknown. Main-table Time left uses actual rate only; Last try is local worker-start time; Description is entered in Scheduler, with missing values blank. Hide details toggles a table of actual per-connection telemetry, never invented segments. HTTP Pause/Resume is active only for verified range sessions; Cancel requests cancellation. Speed exposes validated aggregate limiting and next-start connections; Completion exposes confirmed real shutdown with a visible cancellable countdown.
- Main-toolbar Start/Stop Queue targets Main queue; named queues are controlled in Scheduler. Stop Queue finishes current work without advancing that queue. Stop All stops every queue and requests active cancellation; Stop selected only cancels a selected active item. Remove and Clear finished delete session records, never downloaded files. Show in folder requires a finished record.
- Options actively exposes copied-link detection, off by default and session-only. Check once per second only while the main window is active, all Add/status/Scheduler windows are closed, and Options is closed; offer a bounded HTTP/HTTPS URL for confirmation without autonomous network activity.
- Scheduler is a reused native child for up to 32 named queues (default Main queue), membership assignment from main-table checkboxes, waiting-file Move earlier/later, descriptions, and local once/weekly schedules while Ulos stays open. Non-main deletion reassigns members to Main; active/paused members cannot move. One global transfer is arbitrated by minimum `(queue_order, id)` across running queues. SQLite stores metadata-only destination/status/bytes history, not source URLs or schedules. Restored source-less records cannot start or retry. Queue names, membership, ordering, schedules, descriptions, and Last try are session-only; this is not durable transfer recovery. Browser integration and durable recovery remain future work.

Buttons, Inputs, and Checkboxes keep their default styling in manager, Add, Options, and status views: no `.small()`, `.ghost()`, `.primary()`, or per-control size/padding/color/variant overrides. Layout sizing belongs to wrappers. Use `Toolbar::content`, not `Toolbar::child`, for stock controls: child preparation changes Button size and forces ghost/compact presentation. Icons are stock Lucide assets supplied by Kit’s full asset registration; tooltips require no separate `gpui-tooltip` dependency.

## Schedule design boundaries

Use local Once/Weekly only, never an OS/background service. Once requires a future date; Weekly requires weekdays. Optional earlier stop means overnight, with equal start/stop rejected. Skip nonexistent DST occurrences and choose the earlier ambiguous instant. Wake catches only an unexpired window (no-stop starts only on their local day); ended windows do not replay. Consumed occurrences cannot restart on repeated ticks or manual stop; terminal downloads never retry through recurrence. Scheduler gates both clipboard-read and proposal-delivery phases and keeps its own Kit Root alive after main close.

## Collapsible sidebar

Use stock Kit `Sidebar`, `SidebarGroup`, `SidebarMenu`, and `SidebarMenuItem`, not a nested All-downloads tree. Downloads has All downloads, Finished, Unfinished, and Queue; File types lists `Category::ALL` as seven flat items: Image, Music, Video, Apps, Document, Compressed, and Other. Expanded labels and count suffixes reflect the session model. Kit hides labels/counts in icon mode and supplies rail tooltips; each accessible name still includes its real count.

Keep Kit’s default 255px expanded / 48px collapsed widths and built-in 200ms animation. The app toggle is an unmodified icon Button (`PanelLeftClose` / `PanelLeftOpen`) in `Toolbar::content`, immediately before Add New. Do not use `SidebarToggleButton`: its ghost/small preparation violates the stock-control policy. The existing Kit TitleBar wraps the same toolbar; full-content chrome and native traffic-light spacing are unchanged.

The 2026-10-15 color request adds orange Downloads-group icons and a categorical icon palette: Image teal, Music pink, Video violet, Apps blue, Document green, Compressed amber, Other slate. These are file-type scanning cues, not status colors or a new brand palette. Use the same stock Kit icon/color in the sidebar, filename cell, and Add size preview; retain readable labels and distinct glyphs so hue is never the only cue. Light mode uses darker shades and Dark mode brighter shades. Button/Input/Checkbox styles and Kit selection/hover surfaces remain unchanged.

Collapse is a session-only boolean, expanded by default. Toggling changes presentation only, without refreshing table snapshots or changing queue/filter/search/selection/dispatch order or HTTP behavior. ⌘B / Ctrl+B is scoped to the manager’s `DownloadManager` context. macOS View uses a global typed Collapse Sidebar / Expand Sidebar action that can route from a child through existing menu ownership; non-macOS View keeps Toggle sidebar in-window.

## Native lifecycle and rendering

Every window is opened through Kit and receives its own Root and native OS chrome. Child input, subscriptions, and native path prompts belong to that child window. A pending picker guards native close, dismissal, and submission until resolved. Closing the manager does not close children or discard their shared session owner (including the Scheduler child); closing a status window does not cancel transfer work, but withdraws its shutdown intent/countdown. Remove/Clear finished close status windows for removed records, never delete files. The last-window close requests application quit.

The manager DataTable virtualizes viewport cells rather than eagerly building all record widgets. Transfer polling is change-gated, with stale-rate refreshes; identical status snapshots do not notify. Structural regression counters cover child-input isolation and viewport rendering, not measured opening latency or FPS. Add/status no longer use the modal entrance animation.

## Review boundaries

The main macOS window uses full-content native chrome: no separate visible "Ulos" title strip. Kit `TitleBar` contains the existing stock-control Toolbar, reserves native traffic-light space, and owns dragging/double-click behavior. Window metadata retains the app title. Native menus and child-window titles are unchanged; Windows/Linux keep their existing decorations. No replacement traffic lights or custom-painted titlebar controls.

On macOS, ⌘N opens Add Download from focused search or child inputs, ⌘, requests Options in the main window only, and ⌘Q quits; native Edit uses Kit input actions. Add New has a keyboard shortcut; inputs, selection, and progress have accessible labels. The manager minimum is 880 × 540 logical pixels. Sidebar item focus/arrow navigation and accessibility remain pending review; Kit item rendering alone does not establish full native keyboard support. Minimum-size overflow, keyboard/focus behavior, screen readers, clipboard/picker behavior, and native Linux/Windows rendering still need platform review. Native visual/accessibility capture is not authorized for this update; no first-paint timing or native AX outcome is claimed. The reference guides structure, not an exact-pixel-match or cross-platform visual guarantee.

## Advanced status-window contract

On macOS, the status window has transparent full-content native chrome and the fixed short title Download. Kit TitleBar contains a segmented Kit TabBar with three icon-bearing tabs: Status, Speed, Completion. Native traffic lights remain platform-owned. Compact GroupBox / DescriptionList content and stock state icons communicate actual telemetry. No custom buttons, color overrides, copied branding, or custom-painted tabs are permitted.

The shared footer is outside tab-specific scrolling content. Its 24px stock Kit Progress component has a centered Kit Label overlay with a known percentage or “Percentage unknown”; Kit layout wrappers position the label but do not draw a custom bar. Progress and Pause/Resume/Cancel remain visible on all three tabs. Connection rows reflect the workers actually started, including single-stream fallback and fewer ranges for small files.

HTTP Speed inputs are retained child entities; positive whole-number KiB/s validation bounds the value to 1–1,048,576. Unlimited is explicit. Accepted options are parent-owned; the displayed applied value is not a promise of instant network/server propagation. Connections accept 1–8 only for queued/inactive failed items, and Add offers 1/2/4/8 with default 4. A paused active item is not configurable as an inactive retry.

HTTP file-conflict actions appear for an already-exists failure: Override existing requires Kit confirmation, while Add another file starts a fresh Rename retry. Add Overwrite separately requires its explicit checkbox; parent snapshots revalidate consent. Default Reject remains non-destructive.

Completion's checked state follows the confirmed parent gate, not a speculative local checkbox. Confirmation warns users to save all work and explains the 30-second countdown and OS permissions. Countdowns and Cancel shutdown must be visible; closing that status window cancels intent without cancelling the download. All records must be finished, no task active, and no schedule enabled at the final dispatch check. Enabling a schedule cancels shutdown intent/countdown. Provider errors are shown honestly. No real host poweroff, new native screenshots, or native accessibility outcome is established by this source-level update.

## Torrent integration

The stock Add New dropdown offers HTTP URL / Torrent file; ⌘N retains the HTTP draft shortcut. Torrent picker, drop and OS-open proposals each require native offline review, with a combined 16-draft bound. Show approved name, bytes, manifest (bounded preview), tracker count, destination and Reject/Rename only. No Overwrite, fake speed/connection controls, or automatic networking on open. Download later confirms eligibility for existing running queue dispatch without enabling a stopped queue.

Keep the current category sidebar and shared table; append Type after Description. Single-file torrents use payload file-type categories; multifile payloads are Other. No torrent group or special destination folder. Shared global slot, named queues, scheduler and post-publication completion apply to both protocols. Status reflects actual session pause/bytes/peers; unsupported live rate and connection controls explicitly remain unavailable.

Keep Peers (connected / connecting / queued), Download speed, Upload speed (payload upload disabled), and Trackers configured always visible in the Status summary, not behind Show details. Use engine payload rates independently of verified piece progress; withhold stale active observations through `snapshot.torrent_fresh`, and show zero inactive/terminal activity rather than the last live rate. Discovery/search/connecting/waiting/stall labels and redacted explanations must explain actual state, not promise available seeds or diagnose tracker failure from counts. Keep stock Kit controls and layout stable: this change adds real diagnostics, not decorative panels or discovery/privacy options. No user-torrent success or new native visual verification is implied. Multifile directory removal is metadata-only, not recursive deletion. See [Torrent contract](docs/TORRENTS.md).
